# 多服务器项目及四项 UI 修复

范围：项目添加/选择后串入其他服务器、Todo widget 不可见、过程折叠闪烁、通知开关关闭后不能重开、问答全屏及重复内容。

## 已修复

| 问题         | 原因与改动                                                                                                                                                                                       | 提交     |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------- |
| 项目串用     | 选择其他服务器会话时，原来先向当前服务器保存目录再切换服务器；Git 目录发现还会携带旧目录请求新服务器。现在目录写入、项目对话框、分页、Git 查询和路由均绑定所属服务器，并丢弃过期响应。           | 42d30bb9 |
| Todo 不显示  | 原生组件仅在扩展面板的 TUI 视图中展示，手机输入框附近没有展示入口。现在组件产生有界只读快照，按 aboveEditor/belowEditor 放到输入框附近；状态镜像保存每个 key 的最新值，避免进度更新挤掉 widget。 | 41e2d011 |
| 过程折叠闪烁 | 活跃过程和工具的自动展开状态会先渲染再收回。现在开启过程折叠时首帧关闭，不再由运行状态自动展开；手动展开仍保持，用户直接运行的命令保留原行为。                                                   | 9d3fd52e |
| 通知不能重开 | 重开时重复请求已经获得的系统权限。现在先检查现有权限，授权异步返回不能覆盖更新的关闭操作；后台发送不再主动请求权限。                                                                             | e35655e0 |
| 问答显示     | 新增全屏/退出全屏，答案不丢失；题目和选项各显示一次，详情在原位置展开；Esc/返回先退出全屏而非取消问答。草稿按服务器、会话、worker generation、request ID 隔离。                                  | fd39c2b9 |

未自动删除旧的项目记录。两个服务器确实使用相同目录名也是合法情况，不能仅凭路径相同判断污染。请先切到对应服务器核实，再决定是否从项目菜单移除记录；本轮没有删除任何项目文件。

## 更新要求

**Todo 的修复同时需要新 APK 和新 server/worker。** 仅更新 APK，旧 worker 不会发出组件快照。其余改动主要在前端，Web 用户也要加载新前端资产。

- APK 沿用已有开发签名，不安装到设备、不清除应用数据。
- Linux ARM64 / Termux ARM64 离线包包含对应 server、worker 和 Web 前端；不能混用两种平台的 Node 和 PTY。
- 使用新目录解压，保留旧包和数据备份。停止自己的测试实例后，通过相同的 `PIUI_HOME` 指向数据目录。不要让新旧服务同时写同一份数据。
- 没有更新用户正在运行的服务，没有改个人插件、Pi 配置、凭据或系统通知权限。
- 问答仍遵守原插件 RPC 协议：已有编号多选、自定义输入和取消语义不变。本轮没有替换成新的结构化问卷协议。

## 过程折叠回归（e8b71df8）

上报症状：开启过程折叠后，流式过程中过程内容出现在用户消息气泡上方，且完全不折叠。

两个独立根因都在前端：

1. `packages/app/src/features/chat/chatPageModel.ts` 的 `buildProcessTimeline` 分两趟输出：第一趟把系统条目（压缩摘要、custom 条目）直接输出并结束当前回合，第二趟才按回合输出用户消息与折叠壳。于是第一趟输出的内容和它之后失去归属的助手全部排在**所有用户消息之前**，且不再进壳。改为单趟遍历 + 显式 slot 列表输出，系统条目不再截断回合。
2. `packages/app/src/pi/selectors/index.ts` 把 `custom_message` 无条件当可见行。pi 的语义是 `display === false` 不进对话流（模型专用上下文，例如 plannotator 注入的 framing）。这类隐藏条目被渲染成行后正好插在用户消息与助手之间，触发上面的顺序错乱，并让助手脱离折叠壳。现在 `display !== true` 直接跳过，且不断开相邻的 bash 工具组。

新增回归覆盖：`packages/app/src/features/chat/ChatArea.test.ts` 两例（系统条目保持在原位、页首孤立助手不平铺）、`packages/app/src/pi/selectors.test.ts` 三例（隐藏 hook 不显示、`display=true` 保留、隐藏 hook 不断开 bash 组）、以及浏览器级 `scripts/smoke-timeline-order.mjs`（412×915，断言行顺序、隐藏 hook 无行、流式中壳保持折叠、回合结算、点击展开）。

本轮只改前端：新 APK 必须更新；server/worker 不依赖本轮改动（`mock-session.ts` 只加了 `mock-slow:` 慢回合夹具用于回归测试）。

## 仍需实际设备验收

浏览器测试不能替代 Android 的真实系统通知、IME、后台恢复和弱网测试。没有把这些项目标为已通过。

1. A 添加独有项目，切 B 不应出现；再在全局会话列表跨服务器跳转，检查两侧保存列表。
2. 使用匹配的新 worker 创建 Todo，输入框附近应显示组件；切服务器/会话不应显示另一侧任务。
3. 开启过程折叠，观察 AI 工具开始和完成时均不自动展开；手动展开后状态更新不应立刻收回。
4. 已授权通知时关闭再开启，不应要求撤销系统权限；实际完成一次响应检查系统通知。
5. 问答输入一段文字，再全屏、退出全屏，文字应保留；长选项展开后不出现第二份副本；中文选词 Enter 不应提交。
